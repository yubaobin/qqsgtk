# 审批流

## 概述

审批流是对业务操作进行分级审核控制的机制，支持串行、并行、条件分支等多种流转模式。

## 核心概念

| 概念 | 说明 |
|------|------|
| 流程定义（ProcessDef） | 审批模板，含节点、条件、参与者规则 |
| 流程实例（ProcessInst） | 某次具体审批的运行时对象 |
| 节点（Node） | 流程中的步骤，如“部门经理审批” |
| 任务（ApprovalTask） | 节点上待处理的审批项 |
| 动作（Action） | 通过、驳回、转办、加签 |

## 节点类型

| 类型 | 行为 | 示例 |
|------|------|------|
| 串行节点 | 按顺序依次审批 | 经理 → 总监 → CFO |
| 并行节点 | 多个人同时审批，全部通过才进入下一节点 | 会签 |
| 条件节点 | 根据表达式走不同分支 | 金额 > 10 万需 CFO 审批 |
| 抄送节点 | 仅通知，不阻塞流程 | 抄送 HR 备案 |

## 审批动作

| 动作 | 效果 |
|------|------|
| 同意 | 进入下一节点或结束流程 |
| 驳回 | 退回至指定节点或发起人 |
| 转办 | 将当前审批任务交给他人处理 |
| 加签 | 在当前节点前/后插入临时审批人 |
| 撤回 | 发起人未结束前收回申请 |

## 数据模型

```
ProcessDefinition
  └── Node[]
        └── ParticipantRule（指定人/角色/上级/表达式）

ProcessInstance
  ├── definitionId
  ├── businessKey（关联业务单号）
  ├── status: RUNNING / APPROVED / REJECTED / WITHDRAWN
  └── Task[]
        ├── assigneeId
        ├── status: PENDING / APPROVED / REJECTED
        └── comment
```

## 业务规则

- 同一节点多人串行时，前一人未处理，后一人不可见
- 并行节点需配置通过策略：全部通过 / N 人通过 / 比例通过
- 驳回可配置：直接结束、回到上一节点、回到发起人
- 超时未处理：自动提醒、自动转办或自动通过（按配置）

## 与任务管理的关系

- 审批流关注“决策过程”，任务管理关注“执行过程”
- 审批通过后，可自动生成执行任务
- 任务完成可作为审批的前置条件（通过表达式判断）

## 扩展点

- **动态表单**：每个流程绑定不同的申请表单
- **代理机制**：请假期间自动委托给指定人
- **版本管理**：流程定义修改不影响运行中的实例
