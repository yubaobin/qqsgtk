# 多租户

## 概述

多租户（Multi-Tenancy）是指单一系统实例服务于多个租户（组织/客户），租户间数据与配置相互隔离。

## 隔离方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 独立数据库 | 每个租户一个数据库 | 隔离性最强 | 成本高、运维复杂 |
| 独立 Schema | 同一数据库，不同 Schema | 隔离性较好 | Schema 管理复杂 |
| 共享 Schema | 同一表，加 tenant_id 字段 | 成本低、易扩展 | 需严格保证过滤条件 |

## 共享 Schema 实现要点

### 1. 数据层过滤

所有查询必须带 `tenant_id` 条件：

```sql
SELECT * FROM task WHERE tenant_id = ? AND id = ?
```

### 2. 租户上下文传递

- 登录后将 `tenantId` 写入线程上下文（如 ThreadLocal、请求上下文）
- ORM 拦截器自动注入 `tenant_id` 条件（MyBatis-Plus、Hibernate Filters）

### 3. 表设计规范

- 所有租户相关表必须包含 `tenant_id` 字段
- `tenant_id` 应加入联合索引，通常放在最左前缀

### 4. 特殊处理

- **平台级数据**：设置 `tenant_id = 0` 或单独表
- **跨租户查询**：仅在管理后台需要，需显式授权
- **定时任务**：需遍历租户或按租户分片执行

## 租户配置

| 配置项 | 说明 |
|--------|------|
| 主题/Logo | UI 个性化 |
| 功能开关 | 按需启用模块 |
| 配额限制 | 用户数、存储量、API 调用次数 |
| 自定义字段 | 扩展业务属性 |

## 注意事项

1. 禁止在代码中硬编码租户标识
2. 缓存 key 必须包含 tenant_id
3. 消息队列消费时需还原租户上下文
4. 导出/报表功能需限制仅当前租户数据
